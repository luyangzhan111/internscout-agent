# Stage 18：目标方向与核心技能推荐

## 目标

在可信推荐基础版上增加目标岗位方向、核心／加分技能与可解释排序，减少公关、营销等明确无关岗位占据技术求职推荐。实施前制定本任务；保留原始岗位、来源去重、样例隔离、五维投递条件和原有技能总覆盖率。

## 开发任务与验收

| 编号 | 开发任务 | 验收标准 |
| --- | --- | --- |
| Q1 | 目标方向输入与契约 | 可多选 AI 应用开发、后端开发、计算机视觉、数据开发／分析、前端开发、测试开发、运维／DevOps、安全研发。空列表表示不限；拒绝未知方向和非列表输入，去重保持用户顺序。返回本次方向与排序版本，不由模型修改。 |
| Q2 | 岗位方向规则与证据 | 明确职位／职责短语才是分类依据。优先标题，清晰公关、营销、产品、项目管理等职位不因正文含 Python／AI 被转成开发岗。泛称算法、工程师或仅词汇命中保持方向待确认；支持多方向岗位。所有方向依据保留原文字段和字符位置。 |

| Q4 | 范围与排除 | 沿用先隔离样例→跨来源分组→全集判断→排序→limit。分类计数互斥为关闭、资格不符合、方向不符、剩余符合／待确认。方向不符单列有限条解释和真实资格结果，不把方向差异称作资格不符合。方向待确认继续推荐；全部方向不符给出明确提示。 |
| Q5 | 可解释排序 | 先资格符合／待确认，再方向一致／待确认，再核心技能覆盖率、加分覆盖率、原总技能覆盖率、匹配技能数、岗位编号。覆盖率按匹配数／分类总数比较，空分类视为缺证据而非全匹配；同分稳定。缺核心技能不直接判资格不符合。没有目标方向时不进行方向排除，旧响应仍能展示。 |
| Q6 | Agent 与当前快照 | 模型仅看到已筛选推荐及有界排除依据，不能改变目标、分类、排序或资格。说明提示核心／加分／未分类证据边界；生成期间来源或内容变化仍重算并舍弃旧说明。空推荐不调用模型，失败保留规则结果。 |
| Q7 | 页面与兼容 | 增加多选方向、每岗方向理由和依据，分别显示核心／加分／未分类技能及匹配数。单列方向排除，保留来源追溯和资格排除。输入变化隐藏旧结果，不自动请求模型；有目标但旧服务未返回相同范围不能宣称已筛选。 |
| Q8 | 质量与回归验证 | 固定人工标注案例覆盖无关岗位含技术关键词、混合方向、泛称未知、要求／加分混合句、否定／任选组、空技能、核心优先于加分堆积、资格优先、跨页与截断前排除、模型降级。用当前17条只读快照比较不限与技术目标推荐；核验原始数据与引用不变，不以合成案例宣称普遍准确率。 |

## 实现约定

- `candidate.target_directions` 默认 `[]`，方向标签由界面翻译；不保存个人档案。
- 推荐结果新增 `direction_fit`（`aligned / uncertain / unrelated / not_requested`）和逐项 `skill_requirements`（`core / bonus / unclassified`），每项关联当前原文快照。
- 响应 `counts.direction_mismatch` 默认 0；`direction_excluded` 独立于原有资格排除，最多 10 条。`counts.evaluated` 仍为去重后独立岗位总数，其五类之和必须一致。数据范围原记录等式保持。
- 排序只依据规则字段，核心与加分覆盖率使用分数比较；缺乏该类证据时排在有证据项之后，不把未知显示为满分。原总覆盖率仍单独展示，不叫录用概率。
- 首版仅识别有限明确表达，不用模型补造岗位方向或技能门槛；不做不同 URL 模糊合并、不新增数据源、不自动投递、不删除岗位。
