# Stage 16：Agent 推荐中的技能、投递条件与原文依据

## 目标与判定约定

将 Stage 15 条件检查用于 Agent 推荐：每张推荐卡片同时显示确定性技能覆盖率、匹配／缺失技能、五项条件与原文依据。规则结果是主结论，模型仅提供补充说明。

- 用户提交的结构化技能与条件是唯一档案来源；不从模型参数或自由文本补填个人条件。未知仍是未知。
- 读取当前岗位全集，先计算技能与资格，再按符合、待确认排序；同组按技能覆盖率、匹配技能数、岗位编号稳定排序，最后截取展示数量。不能先取技能前几名再检查条件，也不能沿用旧城市字符串精确过滤。
- 明确不符合与关闭岗位不进入推荐列表，单列数量及有限条阻断依据供复核。待确认保留参与推荐，展示上限导致未展示时明确提示数量。
- 全部待确认仍展示；全部不符合与空库分别说明。没有模型／模型出错时保留规则结果，并明确补充说明不可用，不伪装成成功模型回答。
- 每次请求重新计算；模型等待期间岗位变化则重算、舍弃旧模型说明。页面修改输入后隐藏旧结果，重新点击才发起推荐。
- 本轮新增 `/api/agent/recommend` 作为结构化推荐入口；保留 `/api/agent/query` 与原工具协议，避免改变既有自由问答与技能匹配行为。

## 开发任务与验收标准

| 编号 | 开发任务 | 可检查的验收标准 |
| --- | --- | --- |
| A1 | 结构化推荐契约 | 技能至少一项，资格字段沿用五维契约，展示上限 1–50；区分缺失／0／不限。响应包含推荐、排除原因、分类总数、判断时间、说明来源。 |
| A2 | 全量判断与排序 | 低技能但条件符合排在高技能待确认之前；前五个高技能都不符合、第六个符合时，第六个仍入选；多城市岗位不被旧过滤丢失。 |
| A3 | 三态保留与排除 | 未填学历不能变成符合；待确认保留；不符合与关闭不推荐；空库、全不符合、全待确认分别有明确说明；总数与展示数一致。 |
| A4 | Agent 绑定与依据 | 专用推荐工具只读取本次绑定的规则快照，拒绝模型覆盖候选条件。模型第一步直接回答也有结构化卡片；模型可见技能、状态和压缩原文证据；前后端校验引用与岗位一致。 |
| A5 | 当前数据与降级 | 岗位更新后判断／引用改变；模型调用期间修改或关闭岗位，最终响应重算并舍弃过期说明；模型缺配置、超时或运行失败仍提供规则结果。候选信息不入库。 |
| A6 | 推荐页面 | 同时填写技能与五类可选条件；展示符合优先的顺序、技能匹配、五项状态、原文引用、待确认原因和排除原因；输入变化隐藏旧卡片；不把技能覆盖率叫录用概率。 |
| A7 | 回归与体验 | 规则／工具／API／页面测试覆盖上述边界；旧接口、三工具基线、导入更新、独立条件页回归通过；真实岗位快照只读验证，虚构档案明确标注，不报告通用准确率或虚构模型运行。 |

## 首版边界

真实快照验收发现旧技能词表未识别岗位明确出现的 PyTorch、OpenCV；本轮补齐这两项大小写规范与原文识别，保留原计分公式和严格标识符边界，避免 `pytorch_lightning`、`opencv2` 被误识别。

沿用有限规则覆盖与个人本地使用范围；不新增数据源，不持久化个人档案，不自动投递。AI 补充说明不拥有排序或资格结果，也不能保证完全没有自然语言错误，页面将其与规则结果明确区分。岗位未写或解析不支持时仍须人工确认。按次读取数据库，不主动推送外部更新。

- 最终完整离线回归：`1165 passed in 68.06s`，比 Stage 15 增加 114 项；覆盖新规则服务、绑定工具、接口、页面与两项技能识别，以及原有导入、更新、技能匹配、Agent、检索和独立条件检查。
- 定向验收包含：跨页第 101 个符合岗位不被提前截断；符合优先于高技能待确认；未知保留；模型尝试补填学历被拒绝；首轮直接回答仍有规则卡片；错误和超时降级；运行期间关闭岗位后重算并舍弃旧说明；持续更新返回 409。
- 新推荐入口只在显式请求且有可推荐岗位时构造模型；最多 3 轮，专用 HTTP 阶段超时 8 秒，无自动重试。旧自由问答和原工具协议保持回归通过。失败轨迹未知时不会以 0 冒充模型调用次数。
- 当前本地库只读验收 17 条岗位（含 10 条 OPPO 真实快照），使用虚构档案：技能 PyTorch、2027 届、硕士在读、正式经验 0 月、深圳、可实习 3 月。得到 7 条待确认推荐、10 条明确不符合、0 条关闭；所有原文引用、同快照技能和资格、排序及计数经前端契约验证。
- 实际 CV 岗位首条推荐正确显示已匹配 PyTorch、缺失 OpenCV、技能覆盖率 50/100，同时学历／届次等仍待确认；没有把技能覆盖率当作资格或录用概率。
- 关闭 AI 和缺少模型配置两条真实服务路径均验收通过，规则卡片一致；原 17 条岗位和导入历史完全不变。模型解释链路采用模拟模型离线测试，本轮没有真实模型或 embedding 调用，不构成模型效果或通用准确率评测。
- 浏览器已实测技能与五项条件联合填写、获取推荐、展开真实 CV 岗位的原文依据，并确认页面单列排除样例入口；页面结果与接口一致。验收截图已保存，随后清空虚构档案，保留“Agent 推荐”入口并关闭本次会话的 AI 补充说明，便于用户填写自己的信息体验。

首版仍有有限规则与词表覆盖、最多 50 条推荐和 10 条排除样例、没有外部更新推送等边界。展示上限导致的未展示数量会明确说明；需要长期个人档案或更多招聘写法支持时另行推进。
