# 岗位库：真实导入与更新

本功能是当前工作区的 Stage 14 改动，尚未发布为新版本。开发任务与验收见 [任务清单](tasks/stage-14-real-job-ingestion.md)。

## 开始使用

按 [部署说明](deployment.md) 启动后端和 Streamlit，在 `http://127.0.0.1:8501` 打开界面。

1. **岗位库**：空库可直接选择 **导入真实岗位** 或 **加载演示岗位**。已有数据时可浏览、分页并按来源／状态筛选，查看原文、来源链接及更新时间。
2. **导入与更新 → 手动导入岗位**：填写岗位名、公司、城市、来源链接，粘贴岗位职责与任职要求；没有核对招聘状态时保留“待确认”。
3. **导入与更新 → 刷新 OPPO 岗位**：输入可选关键词和数量上限，手动刷新一批岗位。运行结果和近期记录会显示新增、更新、未变化、失败，以及截断提示。
4. **投递条件**：针对当前页岗位填写个人条件，检查五类门槛与原文依据，详见 [投递条件判断](application-eligibility.md)。

上述功能和规则推荐都可以在没有 DeepSeek 或 embedding 密钥时运行。手动导入保存原链接和粘贴的文本，之后可从页面点击链接到招聘源核对。DeepSeek 用于用户主动开启的 AI 补充说明和原自由问答入口。

## 重复导入和更新规则

- 手动岗位以规范化的来源链接识别。重复提交相同链接更新原记录，岗位 ID 不变。链接中的路径和查询参数保留，片段 `#...` 不参与身份。
- 手动填写的来源岗位 ID 仅作元数据，避免不同招聘网站使用相同 ID 时互相覆盖。更换来源链接会新建一条记录。
- OPPO 以来源＋官网岗位 ID 识别；同名同城的不同岗位可以同时存在。
- 不同来源不会自动合并。Mock 无来源 ID 时仍使用原演示去重规则。
- 导入是完整岗位快照，不是局部字段补丁：再次提交时请保留希望保存的可选字段。
- 内容或状态改变更新 `updated_at`；完全相同的内容只刷新观察时间，计为“未变化”。

## 状态与新鲜度

`unknown` 为待确认，`active` 为来源返回或用户确认在招，`closed` 为明确关闭。手动导入的观察／检查时间只代表系统处理时间，不代表在线核验。旧库升级不会补造“今天已核验”的时间。

本轮不因某次刷新没有看到一个岗位而自动关闭它。OPPO 只覆盖本轮实际获得的岗位；关闭判断和自动失效检测仍需后续实现。Agent 的结构化搜索／匹配排除已关闭岗位，详情接口保留其历史记录。

## 刷新边界与错误

- 默认最多 2 页／20 条岗位；接口上限为 10 页／100 条。
- 默认每次 HTTP 阶段超时 5 秒，至多两次尝试；仅连接类失败、429 和服务端错误重试。
- 采集使用约 45 秒的跨请求时间预算和请求间隔。同步 HTTP 的阶段超时不保证整个运行恰好在第 45 秒结束，入库也可能增加耗时。
- 单条详情失败不会丢失其他成功岗位。分页数据发生不一致时停止继续抓取并保留此前成功结果。
- 达到页数、岗位数或时间预算会显示“部分完成”，记录在 `warnings`，不虚增失败岗位数。
- 真实请求／解析／保存失败记录在 `errors`。`failed_count` 是失败事件数；一次列表页错误可能对应未知数量的未获取岗位。
- `complete=true` 仅表示本次来源查询范围完整，不保证覆盖官网全部招聘类别。
- 前端等待超时后，操作可能仍在后端进行；先查看运行记录，避免重复提交。进程在中途退出可能留下 `running` 记录，本轮不提供后台队列／自动恢复。

## SQLite 升级和备份

首次启动检测到旧结构时，先在同目录创建 `原数据库名.pre-lifecycle-时间-随机值.bak`，再在事务中迁移。升级保留原有岗位编号、创建时间和所有记录；再次启动不会重复升级。备份已被 Git 和 Docker 构建上下文忽略。

历史身份冲突会保留为独立 `legacy_conflict` 记录，非法旧链接也会保留；普通刷新不会自动合并或修复这些历史行，目前没有人工合并界面。遇到此类记录需要人工核对。

恢复旧结构时，先停止服务，并使用升级前版本的程序；保留现有库后将备份复制为配置的数据库文件。当前版本再次启动旧库时仍会执行升级。备份包含导入数据，请按原数据库管理。

## API 示例

`POST /api/imports/manual`：

```json
{
  "jobs": [{
    "title": "后端开发实习生",
    "company": "填写真实公司",
    "city": "深圳",
    "description": "粘贴岗位原文",
    "source_url": "https://example.com/jobs/123",
    "skills": ["Python"],
    "status": "unknown"
  }]
}
```

上例是输入格式样例，不是真实岗位。每批最多 100 条，整批输入验证通过后才开始写入。服务端将来源固定为 `manual`。

`POST /api/imports/oppo`：

```json
{"keyword": "Python", "max_pages": 2, "max_jobs": 20}
```

两个接口都返回运行记录。HTTP 200 表示任务已返回结果，实际成功程度看 `status`（`succeeded`／`partial`／`failed`）与计数。输入不合法使用 HTTP 422。

- `GET /api/imports?limit=10`：最近运行。
- `GET /api/imports/{run_id}`：指定运行。
- `GET /api/jobs?source=manual&status=unknown&page=1&page_size=20`：岗位库筛选。

所有写入都会维护数据库版本。可选语义索引在下一次 Agent 请求发现版本变化后更新；如果新版本构建失败，本次禁用旧语义索引，避免返回已关闭岗位。索引构建仍在请求路径，后台刷新是后续优化。

这是个人本地使用功能，尚未加入多用户身份隔离和公开部署的访问控制。
