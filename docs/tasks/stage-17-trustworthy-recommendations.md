# Stage 17：可信推荐基础版

## 目标与范围

在 Stage 16 推荐入口实现跨来源去重、样例隔离、待确认原因分类和技能匹配分母。先制定本任务与验收，再实施；保留现有原文、来源记录、三态判定和确定性排序。数据库不删除、合并或改写岗位，不新增数据源、不自动投递、不保存个人档案。

## 开发任务与验收标准

| T2 | 主来源与可追溯性 | 已接入的官网来源优先，其他记录按可用时间与稳定规则选择；原文与技能判断只使用所选的一份快照，不拼接相互冲突的要求。提供组内来源、状态、核验时间与差异提示；官网关闭不能被手动副本重新推荐。 |
| T3 | 样例默认隔离 | 推荐请求增加默认关闭的 include_samples；source=mock 及 example.com／example.org／example.net（含子域）示例链接视为演示记录。默认在分组和模型输入之前隔离，可显式打开；页面标明演示模式，开关变化清除旧结果，不自动请求模型。 |
| T4 | 数据范围计数 | 摘要说明读取记录数、隔离样例数、合并重复数、实际判断的独立岗位数。满足读取数=隔离数+合并数+判断数，原分类数仍完整分区实际判断数；推荐及排除结果可追溯来源。 |
| T5 | 待确认分类 | 每项未知结果提供结构化原因类型与下一步建议：个人信息缺失、原文未说明、无法可靠判断、要求冲突。偏好不提升为门槛；未提及不变成符合；无效证据不变成硬性排除。复杂或多个原因按实际阻止判断的原因给出明确说明。 |
| T6 | 页面与技能分母 | 推荐页与独立条件页展示原因分类及建议。推荐卡显示匹配 N／已识别 M 项以及原分数，分母来自去重后的已识别技能集合；零技能明确显示证据不足；不改计算公式，不让模型提供分母。 |
| T7 | 兼容与验证 | 新字段有安全默认；旧结果缺少原因分类不猜测归因。API、规则、前端契约和界面测试覆盖默认隔离／显式开启、跨页重复、同名不同岗、关闭与来源冲突、模型等待期间更新、四类未知、空分母及排序不变。真实库仅只读检查，区分离线模拟模型与真实模型运行证据。 |

## 选择与边界

- 分组用于推荐展示，岗位库与导入历史保留原记录。来源差异是提示，不替换主来源的原文证据，不臆造统一招聘条件。
- 首版保守使用规范化 URL 和公司／岗位名称识别，不新增跨站模糊匹配。只有模糊相似的岗位继续分别保留；查询参数顺序、普通网页锚点不同也保留为不同记录，避免误合并网页路由中的岗位 ID。
- 来源为手动且不是示例链接，不等同已经验证的真实在招岗位；页面保留其来源与状态说明。
- 原有符合优先、同组按技能覆盖率／匹配技能数／编号排序，以及不符合／关闭排除的规则保持不变。
- 当前库的毕业届次信息不足，因此实际整体符合可能仍为零；不将降低待确认数量当作成功指标。
