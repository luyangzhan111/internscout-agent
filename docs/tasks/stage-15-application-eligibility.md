# Stage 15：有原文依据的投递条件判断

## 目标

对候选人主动填写的信息，逐项检查毕业届次、学历、工作经验、城市和可实习时长，输出“符合／不符合／待确认”及岗位原文依据。通过独立、无需模型的界面和 API 使用；技能覆盖分数保持独立，不作为投递资格。

## 判定约定

- 必须有清楚的硬性条件和足够的候选人信息，才作确定比较；没写、未填写、表述含糊、互相矛盾或超出解析支持范围时标“待确认”。
- “优先／加分／更佳／preferred”是偏好，不作为拒绝条件。只有偏好、没有明确硬条件时，该项仍待确认。
- 明确“不限／无经验要求”是有依据的无门槛，可判符合。候选人经验 0 与未填写不同，城市不限与未填写不同。
- 总评：任何明确硬条件不满足为不符合；否则任一项待确认则总评待确认；五项都通过才为符合。岗位已明确关闭时附独立阻断原因，总评不符合。
- “符合”仅覆盖这五项已识别条件，不代表已通过全部招聘要求或保证录用。专业、技能熟练度、每周到岗天数、到岗日期等仍看原文，不暗中转换为已满足。
- 学历增加“在读／已取得／未说明”输入，避免把在读自动当成已经取得学历；细粒度毕业日期窗口仅有届次时待确认。
- 可实习月数表示可提供的连续时长；不足明确最低要求为不符合，超过岗位有限上界时待确认，需核实是否愿意缩短，不直接作为淘汰条件。
- 每段证据都携带来源字段和起止位置，必须与岗位当前原文精确一致。未知但有相关表述时也展示原文；原文没有相关信息时明确写未找到，不编造引用。
- 判断使用当前岗位内容即时计算，不持久化候选人信息；浏览器会话可保留本次填写。岗位更新或候选人条件变化后必须重新判断，不显示旧结果冒充新结果。

## 开发任务及验收标准

| 编号 | 任务 | 可检查的验收标准 |
| --- | --- | --- |
| E1 | 输入与结果契约 | 五项均可留空；年／月数范围和城市列表校验；0、未知、不限分开。每个岗位固定返回五项结果、总评、说明和证据。 |
| E2 | 保守解析原文 | 支持明确届次／届次列表或区间、学历门槛／枚举、经验与实习时长的月年换算、多城市；偏好不变硬门槛。含糊表达保留引用并待确认。 |
| E3 | 三态比较与总评 | 例如 2027 届对仅限 2026 届不符合；本科对硕士及以上不符合；0 月经验对至少 2 年不符合；深圳意向对北京/深圳符合；3 月对至少 6 月实习不符合。边界相等符合，未知不默认为通过。 |
| E4 | 依据与冲突处理 | 引文可在 title/description/city 原文按偏移复现；学历在读条件、日期窗口、相关项目经验、互相矛盾条件不能靠猜测得出符合。岗位修改后证据与判断刷新。 |
| E5 | 无模型 API | 一次最多 50 个已存在岗位；未知 ID、非法输入返回清晰错误；不需要模型、不调用外部服务、不写入候选人信息。 |
| E6 | 可体验界面 | 新增“投递条件”入口；填写条件，按当前页岗位判断；展示总评、五项细分、待确认原因和原文依据。更改表单或岗位来源后不误显示上次结果。 |
| E7 | 回归和真实样本 | 覆盖五维正反例、缺失、优先、冲突、Unicode 引文和更新重算；原有导入／浏览／Agent 回归不退化。只读当前真实岗位，用明确标注的测试档案检查证据，不把开发样本当真实准确率。 |

## 首版范围

采用可测试的规则解析与比较，无模型费用。解析覆盖有限，遇到未支持写法回到待确认。先提供用户主动检查功能，不自动提交申请、不修改原 JD，也不以未知条件过滤掉岗位。保存长期个人档案、复杂专业经验判断和模型辅助抽取留待后续。

接口：`POST /api/eligibility/evaluate`，输入 `{profile, job_ids}`，返回 `{items, assessed_at}`。日期时间使用 UTC，页面以北京时间显示。

已完成 E1–E7，2026-11-12 验证如下：

- 独立补充审查定位并修正关联任选条件、分行和括号偏好、常见否定、无空格 `base北京` 等作用域问题，纳入回归；不支持的关联关系保守待确认。
- 本地后端已重启加载新功能。只读检查已导入的 10 条 OPPO 岗位快照，使用明确标注的虚构档案（2027 届、本科在读、0 月正式经验、深圳、可实习 3 月），结果不符合 6、待确认 4。逐项引文通过前端契约复核；判断前后岗位仍 17 条，岗位内容与导入历史完全不变。
- 实例：北京 CV 岗位与测试城市冲突；该岗位“能实习6个月或以上优先”不作为拒绝条件。另一 CV 岗位的硕士及以上门槛与测试本科层级冲突；项目管理岗位的至少 6 个月实习要求与测试 3 个月冲突。
- 浏览器实际核验：选择 OPPO 来源、填写虚构档案、判断 10 条岗位、展开五项结果与原文，计数与 API 一致。验收后清空测试档案，保留“投递条件”入口及 OPPO 来源供用户填写个人信息。
- 无真实模型／embedding 调用，无新依赖或数据库结构变更。本轮不重新抓取招聘网站；真实样本仅为库中已有快照的开发核验，不代表实时招聘状态或通用准确率。

剩余边界：首版只覆盖有限语法和城市名称；裸时长、复杂布尔条件、精确毕业日期、领域经验、学历最高限制和未支持城市保守待确认。页面需交互或点“刷新当前页岗位”才检查外部更新，不提供主动推送。候选人长期档案和 Agent 条件判断工具尚未接入。
