# Stage 14：真实岗位导入与更新

## 目标与范围

把已有岗位采集管道变成可日常操作的岗位库：用户可以粘贴真实 JD 导入，也可以按关键词手动刷新 OPPO 来源；同一岗位内容变化时更新原记录，每次运行留下新增、更新、未变化和失败结果。

本轮继续使用 FastAPI、SQLite 和 Streamlit，不依赖模型。保留 Mock 演示入口和现有 Agent。个人档案、资格判断、投递看板、定时任务和自动下架属于后续阶段。

## 状态语义

- `active`：来源本次返回为可见招聘岗位，或用户明确选择已确认在招；仍应回原站核对。
- `unknown`：手动导入未确认或历史数据状态未知；不等于在招。
- `closed`：用户明确确认关闭。本轮不根据列表缺失自动推断关闭。
- `updated_at`：内容或状态最后变化时间。
- `last_seen_at` / `last_checked_at`：系统最近接收／处理该岗位的时间。手动导入的时间不是在线有效性证明。
- `complete=false`：运行被限制截断、部分失败或来源快照不完整，不据此推断未返回岗位已关闭。
- 时间存储采用 UTC，界面提供可辨识的时间显示。

## 接口约定

- `POST /api/imports/manual`：`{jobs: [...]}`，服务端固定来源 `manual`，最多 100 条。
- `POST /api/imports/oppo`：`{keyword, max_pages, max_jobs}`，默认 2 页／20 条，最大 10 页／100 条。
- `GET /api/imports?limit=10`：最近运行列表。
- `GET /api/imports/{run_id}`：运行详情。
- `GET /api/jobs`：增加来源与状态筛选，保留原有分页及筛选。

导入与刷新返回运行记录。上游抓取失败是一个已记录的任务结果，响应使用运行的 `status` 表达；输入错误使用 HTTP 422，未知运行使用 HTTP 404。
