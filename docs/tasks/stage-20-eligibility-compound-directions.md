# Stage 20：学历/在读条件与复合岗位方向修复

## 目标及开始前约定

修复 Stage 19 暴露的两类问题：一般性未知条款掩盖明确学历/在读阻断，以及技术标题覆盖正文直接职责而漏筛复合岗位。先制定本任务，再实施规则；保留原评测数据、金标、报告及旧规则实现。旧30岗从本轮起是开发/回归数据，不能继续称为新留出集。

不调用付费模型或 embedding，不改技能提取词表、核心/加分分类或排序公式，不自动投递。明确未知、真正冲突、逻辑关联无法表达及无可靠证据的要求仍保留待确认。新留出岗位在修复完成前不交给规则开发者，也不按新版输出选取、标注或修订。

## 质量判断及边界

- 旧集用于修复及回归：目标错误修复、偏好不升级硬门槛、未知不凭空晋升符合，不增加无依据资格阻断，核心技能与总分公式不变。
- 新集用于检查泛化：先报告全部结果，再判断改进覆盖了哪些公司/模板/表达；不能只报告总体均值、只选提高的档案，或把多候选对说成不同岗位数。
- 对存在学历/在读明确阻断的标签单列召回和误放行；无该类正例时记N/A，不能用总体一致率遮盖。
- 视觉模型接入/部署可以提供视觉方向证据；AI应用仍需明确Agent、LLM应用或生成式产品交付，不能把所有视觉/模型部署自动归为AI应用。
- 本轮不实施所有段落语义、通用布尔逻辑或岗位理解模型。未覆盖表达保持待确认并列入后续案例。现有样本只支持小规模离线结论。
