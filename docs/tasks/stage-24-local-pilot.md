# Stage 24 P0 · 本地试用候选

交付目标是让第一次接触 InternScout 的人从空岗位库出发，用自己的 JD 得到一次可核对的投递条件判断。启动入口见 [Quick Start](../../README.md#quick-start)。

## 试用路径

1. 从空数据库启动工作台。模型和 embedding 设置可留空。
2. 在 **岗位库** 选择 **导入真实岗位**。填写名称、公司、城市、官网链接，粘贴 JD，点击 **保存 / 更新岗位**。如还没核实招聘状态，保留 **待确认**。
3. 打开 **投递条件**，填写已确定的个人条件并点击判断。展开 **查看五项判断与原文依据**，查看一条可以返回 JD 原文核对的依据。用 **前往岗位来源核对** 打开来源。
4. 空库也可以选择 **加载演示岗位**。这条路径读取项目自带的模拟岗位，卡片明确标注样例。用 **Agent 推荐** 体验演示岗位时，输入一项技能并勾选 **包含演示数据（仅用于体验）**。规则推荐默认可直接运行，AI 补充说明按需开启。

## 发布内容

- 与 Stage 14–23 工作区一致的应用代码、Streamlit 配置与样式、依赖、Docker Compose、测试和本地使用文档。
- 可随试用候选提供的演示岗位位于 `app/fixtures/sample_jobs.html`。自动化上手案例使用合成 JD 和测试域名。
- 维护者的数据库、历史备份、密钥文件、临时目录、真实岗位采集原件、衍生评测语料和逐项报告均保留在本地。只有依赖真实评测语料的历史回放用例在完整语料目录缺席时跳过；日常测试和无密钥验收照常执行。
- 代码许可证由维护者在公开发布前选定。当前候选用于本地试用。
